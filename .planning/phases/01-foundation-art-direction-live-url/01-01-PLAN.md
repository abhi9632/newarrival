<objective>
Stand up the NewArrival application shell and get it onto a public Vercel URL, carrying the
real intro copy as plain text.

This is the Walking Skeleton tracer for the whole project: one route, rendered through the
real build pipeline, served from the real deployment target, reachable from a phone. There
is no database and no API layer in this project by design (scope mode is `prototype`, every
data path is static JSON), so the full stack this tracer must prove is: Next.js App Router
route to build output to Vercel production URL. See SKELETON.md in this directory.

Purpose: a past event deployed in the final five minutes under time pressure. Deploying in
the first phase removes that risk and makes every later push reviewable on a real device.

Output: a running Next.js app at a public Vercel URL, with the URL recorded in HANDOFF.md.
The screen is deliberately undesigned at the end of this plan. Plan 01-02 designs it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry to build machine and Vercel build container | Third party code is fetched and executed during install and build |
| GitHub App authorisation to private repo contents | Vercel is granted read access to a private repository |
| Public internet to Vercel-hosted static site | Anonymous visitors, including judges, reach the deployment |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-SC | Tampering | npm installs during scaffold | high | mitigate | No `## Package Legitimacy Audit` exists because project research was disabled deliberately (PROJECT.md Key Decisions) and there is no RESEARCH.md for this phase. The substitute gate closes the actual vector, which is agent-authored or hallucinated package names: no package name in this plan is chosen by an agent, the dependency set is whatever `create-next-app@latest` from Vercel's own scaffolder emits, and Task 1 carries an automated criterion asserting `dependencies` is exactly `next,react,react-dom` so a hand-added package fails the task. Adding any package is out of scope for this phase. |
| T-01-01 | Information disclosure | Vercel GitHub App scope on a private repo | medium | mitigate | Task 2 instructions require "Only select repositories" scoped to `newarrival`, never "All repositories". |
| T-01-02 | Information disclosure | Secrets committed to the repo | high | mitigate | No environment variable is created for this project; Task 2 explicitly forbids adding any, and forbids pasting a token into the session. `.gitignore` already excludes `.env` and `.env.*`. |
| T-01-03 | Elevation of privilege | Public production URL behind Deployment Protection | medium | mitigate | Task 2 step 6 requires confirming Vercel Authentication is disabled for Production. Task 3's `curl` gate fails on the `401`/`302` that protection produces, so a wrong setting cannot pass silently. |
| T-01-04 | Denial of service | Public static site | low | accept | Static assets on Vercel's CDN. No server route, no database, no form, no API. Nothing to exhaust, and hobby-tier limits are acceptable for a single-day demo. |
| T-01-05 | Repudiation | Commit authorship | low | mitigate | Task 1 runs `git config user.name` before committing per CLAUDE.md GIT IDENTITY; the repo also carries `scripts/hook-block-bad-git-identity.sh`. |
</threat_model>
