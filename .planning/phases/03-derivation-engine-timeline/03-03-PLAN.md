<objective>
Turn the derived obligation set into the emotional centre of the product: a dated timeline of cards, each naming its agency, its computed status, its instrument and its source, each openable for the plain language consequence. Then judge the screen against the locked Signature and answer the concept's third assumption with evidence before Phase 4 starts.

Purpose: this is the screen the judge looks at for most of three minutes and the surface Phase 4's cascade animates. A generic screen is a bug on this project, not a cosmetic issue, and a timeline that reads as a default component library list would undercut the one claim the product makes about itself.

Output: `src/components/ObligationCard.tsx`, the timeline on `/timeline`, four visual gate screenshots, the gate answers in `design-system/README.md`, and the `ASSUMPTION 3` decision line in `HANDOFF.md`.

Time budget: about 45 minutes of the phase's 90.
</objective>

<user_story>
**As a** new arrival who has just been handed a list of things the law expects of her,
**I want to** see each one dated, attributed to the agency that owns it and traceable to the rule it came from,
**so that** I can act on it and check it myself rather than being asked to trust an app.
</user_story>

<constraints>
Binding, from `docs/CONCEPT.md` Hard constraints and `.planning/PROJECT.md` Constraints.

- Scope is `prototype`. No backend, no database, no auth, no API route, no server side data fetching.
- No external network call at demo time. The only outbound link on the screen is the source anchor a judge clicks deliberately.
- No personal identifier collected or persisted. No browser storage of any kind.
- No em dash and no en dash used as a pause in any visitor facing copy, label or on screen text.
  The dash gate is written with UTF-8 byte escapes because the bracketed backslash-u form used in the
  Phase 1 plans does not expand in this machine's Git Bash: it degrades into a character class of the
  letters and digits inside the escape and matches almost every line. The byte escape form was verified
  on 2026-09-22 to match a real dash and nothing else. Do not rewrite it back.
- No advice framing. The card states what the rule says and what happens if it is missed, and cites the instrument. It never states what the reader ought to do. The three banned phrases are the ones named in `docs/CONCEPT.md` line 49; the acceptance criteria grep for them case insensitively.
- Do not build the Ledger. No dollar figure of what a user is owed or at risk of appears on any card, in any badge or in any total.
- Zero new dependencies. The disclosure is a native details element, the dates are formatted from their own string parts, and no animation library enters here. `animate` belongs to Phase 4 and only after the static layout is settled.
</constraints>

Export two module level record constants alongside the component:

- `STATUS_LABEL`, mapping each member to visitor facing text: overdue, due soon, upcoming, and standing condition, each capitalised as a label.

The card's always visible region carries, in this reading order:

1. The status pill, text from `STATUS_LABEL` and colour from `STATUS_CLASS`. This is TIME-03 and its value was computed by the engine against the injected reference date, never hardcoded.
2. The due date, formatted for reading. Format it from the ISO string's own parts with a month name array rather than constructing a Date, so the displayed day cannot drift by one against the computed day. For a standing obligation show the standing label instead of a date. Where `daysUntilDue` is present, a short relative phrase beside the date earns its place, written without advice framing.
3. The title as the card's heading.
4. The agency name. This is TIME-02 and it is the label that makes the timeline read as four agencies rather than one app's opinion.
5. The instrument name, in full, as text. This is SRC-01 and the requirement says not hidden behind a click, so it stays in the always visible region even though it is the longest string on the card.
6. The source link, an anchor to `sourceUrl` opening in a new tab with a rel attribute carrying both noreferrer and noopener. This is SRC-02, and the rel attribute is also the mitigation that stops the opened page reaching back through the opener handle. Give the link accessible text that names what it opens rather than a bare word, since a screen reader user hears the link text out of context.
7. The last checked date from `verifiedOn`, labelled so a judge reads it as the date the rule was checked against its source. This is SRC-03 and it is cut item four: keep it as one self contained element so removing it is a single deletion.

Only the plain language `detail` goes behind a disclosure, as a native details and summary pair. That is TIME-04, it needs no state and no library, and it is keyboard accessible by default. The summary text names what opening it reveals: what the rule requires and what happens if it is missed.

Keep `data-obligation-id` set to the obligation id on the card's root element. The phase's end to end build assertion greps the built output for a pinned record id and it must still hold after this pass.

Then rewrite the list in `src/app/timeline/page.tsx` as the timeline proper. Split the derived array into the dated obligations and the standing ones, using the presence of `dueDate` rather than any facet or module test. Render the dated ones as an ordered list in the order the engine returned them, which is already ascending by date, under a heading that names it as the dated timeline. Render the standing ones after them, under their own heading naming them as standing conditions that apply for the whole stay. Do not invent a date for a standing obligation to force it onto the dated axis; most of the corpus is standing conditions and pretending otherwise would put a fabricated deadline on screen, which is the one thing this product cannot do.

Give the dated list a visible time axis of some kind so it reads as a timeline rather than a table of rows: the Signature in `design-system/README.md` decides what that is. Whatever it is, it must survive a 375 wide viewport, which Task 2 screenshots.

Every string added here is visitor facing copy and obeys the copy rules: no em dash, no en dash used as a pause, no advice framing, no angle brackets, plain language.
