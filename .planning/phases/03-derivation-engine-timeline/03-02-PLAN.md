Render four labelled controls in one section above the obligation list, in this order, matching the four facts INTAKE-02 names:

1. Visa subclass, a native `select` fed by `SUBCLASS_OPTIONS`.
2. Citizenship, a native `select` fed by `CITIZENSHIP_OPTIONS`.
3. Arrival date, a native `input` of type date bound to `profile.arrivalDate`.
4. State, a native `select` fed by `STATE_OPTIONS`.

Every control is fully controlled: `value` comes from the profile state and `onChange` writes one field back through a single setter that spreads the previous profile. Do not hold four separate `useState` calls. One object is what makes ENGINE-05 structural rather than four independent wiring jobs, and it is the shape Phase 4 perturbs.

Each control gets a real `label` with `htmlFor` matching the control's `id`. The labels are visitor facing copy and obey the copy rules. Use the option lists' labels rather than raw codes, so a judge reads country and state names rather than two letter codes.

Render a fifth control, the course end date, as a native date input bound to `profile.courseEndDate`, **only when** the currently derived obligations contain at least one whose `anchor` field is the course end anchor. Compute that from the derived array, never from `profile.subclass`. Reading the subclass here would be a hardcoded per profile behaviour one layer above the engine, which is exactly what ENGINE-01 forbids; reading the derived set is the same generic derivation applied to the chrome. This control is also the value Phase 4's perturbation drags, so its state must live here, not inside a child.

There is no `form` element on this page. No form means no default submit path, which means no navigation and no reload, which is ENGINE-05 satisfied by construction rather than by an event handler that calls a prevention method. The derived obligations come from a `useMemo` over the profile state, the reference date and the imported corpus, so every control change recomputes the full set in the same render pass.

Do not create a `components/` tree in this task. The intake is roughly forty lines of markup in one file and a component boundary here would be structure for a codebase that does not exist yet. Plan 03-03 creates the one component this phase actually needs, the obligation card, because that one has its own disclosure state.

Style against the tokens already in `src/app/globals.css` and reinforce the Signature named in `design-system/README.md`. Full styling and the visual gate are plan 03-03's work; this task's job is that the controls exist, are labelled, are reachable by keyboard and are not visibly unstyled.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input to profile state | Four control values cross into the object every derivation reads. They are constrained to the locked matrix by the option lists, and the date inputs by the native date type. |
| profile state to engine | The intake is the only writer of the object the engine reads; a malformed profile would produce a wrong timeline rather than an error. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-06 | Tampering | profile facet values from the selects | medium | mitigate | Options are rendered from the three locked option lists in `src/lib/profile.ts`, so a select cannot produce a facet value outside the locked matrix, and an unmatched facet value simply derives nothing rather than throwing |
| T-03-07 | Tampering | per profile branching reintroduced in the chrome | high | mitigate | Acceptance criteria negative grep the component for facet value comparisons and for preset ids, so ENGINE-01 cannot be defeated one layer above the engine |
| T-03-08 | Information disclosure | the four profile facts | low | accept | Values live in React state only, are never persisted and never transmitted. The acceptance criteria negative grep `src/` for every browser storage API and for network calls |
| T-03-09 | Denial of Service | a date input with an absurd value | low | accept | A far future or far past date derives a valid but useless timeline. There is no backend to overload and no persistence to corrupt, so validation here would be code with nothing to protect |
| T-03-SC | Tampering | npm, pip and cargo installs | low | accept | This plan installs nothing. The four controls are native select and date input elements, which is why no date picker package is required and none is claimed |
</threat_model>
