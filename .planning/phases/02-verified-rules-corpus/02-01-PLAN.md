<objective>
Establish the rule record schema, the typed corpus entry point, and the validation script that makes an unsourced record impossible to commit. Then prove the whole layer end to end with one real, live-verified subclass 500 condition record.

Purpose: RULE-01 is the gating requirement for the entire product. The pitch claim is "this is auditable", and a single unsourced or wrong figure on stage destroys it. The validator is the acceptance evidence for RULE-01, not a manual read-through. It exists before any content is written so the content task physically cannot produce an unsourced record.

Output: `src/lib/rules.ts`, `src/data/rules.json` seeded with one verified record, `scripts/check-rules.mjs`, `scripts/fixtures/bad-rules.json`, and an npm script.

Time budget: about 20 minutes of the phase's 60.
</objective>

1. Every number, day count, dollar amount and percentage that lands in `src/data/rules.json` comes from a page fetched during this phase with WebSearch or WebFetch against a live `.gov.au` host. Write `src/lib/rules.ts` containing three things and nothing else:

(a) Exported const arrays of the locked matrix values: SUBCLASSES holds `500` and `482`, CITIZENSHIPS holds `IN` and `IT`, STATES holds `VIC` and `NSW`. The matrix is locked. A third value of anything is refused.

(b) An exported `RuleRecord` interface with exactly these fields:
- `id`, a stable unique kebab case string, for example `visa-500-8533-address`
- `module`, one of `visa`, `work`, `health`, `tax`, `tenancy`
- `title`, the short visitor facing card label
- `detail`, the visitor facing plain language body stating what the rule requires and what happens if it is missed
- `agency`, the owning agency display name, for example `Department of Home Affairs`
- `instrument`, the named legal instrument or agency page title, for example `Migration Regulations 1994, Schedule 8, condition 8533`
- `sourceUrl`, an https URL on a `.gov.au` host
- `verifiedOn`, an ISO `YYYY-MM-DD` date, the day the source page was fetched live
- `appliesTo`, an object whose keys are drawn from `subclass`, `citizenship`, `state`, each value a non empty array of allowed values for that facet. An absent key means the record applies to every value of that facet. An empty object means the record applies to everyone.
- `due`, an object with an `anchor` of `arrival`, `courseEnd`, `fixed` or `ongoing`. `arrival` and `courseEnd` carry an integer `offsetDays`. `fixed` carries an ISO `date`. `ongoing` carries neither and means a standing condition with no single deadline.

(c) An exported `rules` const that imports `../data/rules.json` and casts it once to `RuleRecord[]`. Use a single cast through `unknown` and mark it with a `ponytail:` comment naming that `scripts/check-rules.mjs` is the real gate on the union valued fields, since TypeScript widens JSON string literals and cannot check them. This is the one import path Phase 3 consumes.

Write `src/data/rules.json` as a bare JSON array, pretty printed with 2 space indent, containing exactly ONE record: subclass 500 condition 8533, the residential address notification condition. Verify it live first per the verification method above. Search Home Affairs for the subclass 500 visa conditions page, likely under `immi.homeaffairs.gov.au`, fetch it, and take the day count, the obligation wording and the consequence of breach from that page. The `due.offsetDays` value comes from the fetched page, not from this plan, and not from memory. Set `appliesTo` to subclass `500` only, `module` to `visa`, `due.anchor` to `arrival`, and `verifiedOn` to today's date.

Copy rules for `title` and `detail`, both are visitor facing and render directly on the timeline: no em dash and no en dash used as a pause, use a comma, a colon, a semicolon or split the sentence. No advice framing, the text states what the rule says and what happens if it is missed, never what the reader ought to do. No HTML angle brackets.

Write `scripts/check-rules.mjs`, plain Node with zero dependencies. It reads the corpus path from `process.argv[2]`, defaulting to the corpus path resolved above, parses the JSON array, and checks every record. Every violation prints one stdout line in the form `FAIL <gate>: <record id>: <what is wrong>`. On any violation it exits 1. On a clean corpus it prints `OK <n> records` and exits 0. Implement these three gates in this task and leave the rest for Task 2:
- `required-field`, every one of id, module, title, detail, agency, instrument, sourceUrl, verifiedOn is a present non empty trimmed string
- `source-host`, sourceUrl starts with `https://` and its parsed hostname ends with `.gov.au`
- `verified-date`, verifiedOn matches `YYYY-MM-DD`, parses to a real date, is not in the future, and is not more than 30 days old

Add `"check:rules": "node scripts/check-rules.mjs"` to the package.json scripts block. Do not add any dependency, this phase installs nothing.

Extend `scripts/check-rules.mjs` with the remaining eight gates, keeping the same `FAIL <gate>: <id>: <message>` stdout line format and the same exit 1 on any violation:

- `duplicate-id`, no two records share an id
- `module-name`, module is one of visa, work, health, tax, tenancy
- `applies-to`, appliesTo is an object, its keys are a subset of subclass, citizenship and state, each value is a non empty array, and every element is an allowed value for its facet. Subclass allows 500 and 482, citizenship allows IN and IT, state allows VIC and NSW. This gate is what keeps the locked 2 by 2 by 2 matrix locked.
- `due-shape`, due.anchor is one of arrival, courseEnd, fixed, ongoing. arrival and courseEnd require an integer offsetDays and forbid date. fixed requires an ISO YYYY-MM-DD date and forbids offsetDays. ongoing carries neither.
- `dash-copy`, neither title nor detail contains U+2014 or U+2013. Write these in the script as the escape sequences `\u2014` and `\u2013`, never as the literal characters, so a repo wide dash sweep does not flag the validator itself.

The deny list holds the phrases named as forbidden in the Hard constraints block of `docs/CONCEPT.md` line 49 plus their close variants: the second person modal recommendation form, the second person eligibility assertion form, and the first person plural recommendation form. Read line 49 and lift the exact literals from it into the array. This gate is a legal constraint, not a style preference: unregistered paid immigration assistance is an offence in Australia and the product's defence is that it cites rules rather than advising on them.
- `markup-copy`, neither title nor detail contains `<` or `>`. The corpus is plain text that will be rendered by React; this closes the injection path at the data layer rather than trusting every future component.
- `rhca-branch`, a corpus level gate, not a per record one: at least one record has appliesTo.citizenship equal to exactly `["IT"]` and at least one has it equal to exactly `["IN"]`. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live .gov.au page to corpus | A human readable legal page is transcribed into machine readable JSON by an agent. Transcription error is the primary risk in this phase. |
| corpus to rendered UI | Corpus strings cross into React components in Phase 3, including one string that becomes an anchor href. |
| model memory to corpus | The lowest trust input of all. Any figure that arrives from training data rather than from a fetched page is unverified by construction. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | `src/data/rules.json` figures | critical | mitigate | Every figure fetched live during this phase; `verified-date` gate rejects a stale or future date; cut rather than guess when a figure cannot be verified |
| T-02-02 | Spoofing | `sourceUrl` field | high | mitigate | `source-host` gate requires https and a hostname ending in `.gov.au`, so a private site cannot be cited as an official source |
| T-02-03 | Repudiation | audit trail of a figure | high | mitigate | `required-field` gate makes `instrument` and `verifiedOn` non optional, so no record can exist without naming what it came from and when it was checked |
| T-02-04 | Elevation of Privilege | corpus copy rendered by React | medium | mitigate | `markup-copy` gate rejects angle brackets in `title` and `detail`; `source-host` gate blocks a `javascript:` scheme reaching an href |
| T-02-05 | Information disclosure | user profile data | low | accept | No personal identifier is collected or persisted anywhere in the product, and this phase adds no storage, so there is nothing to disclose |
| T-02-SC | Tampering | npm/pip/cargo installs | low | accept | This phase installs nothing. The validator is plain Node with zero dependencies, so no package legitimacy audit is required and none is claimed |
</threat_model>
